# Project Guidelines & Rules

## Code Style & Comments
* **No Comments:** NEVER write inline comments, block comments, or paragraph-style explanations in code files.
* **Docstrings:** You may only write docstrings that are brief, single-line, and directly to the point.
* **Preserve History:** Preserve existing comments in the codebase unless explicitly instructed to modify or delete them.

## Source Naming Conventions
* **Domain Consistency:** Naming conventions across different legal sources must be strictly respected.
* **Source Prefixes Examples:**
  * `wrc_ie` — Workplace Relations Commission (Ireland)
  * `sc_gb` — Supreme Court (Great Britain)

## Workflow & Planning
* **Consult Before Scaling:** Never begin large-scale code changes, refactoring, or major pipeline steps without first presenting a plan and getting explicit approval.
